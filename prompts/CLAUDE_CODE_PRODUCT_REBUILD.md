## 0. Claude Code가 지금 해야 할 일

현재 프로젝트를 읽고 **1단계: 현재 위치에서 자유 드라이브 시작 + 안정적인 주행 기록**을 실제 코드로 구현하라. 계획만 제시하거나 별도 웹 목업을 만들고 끝내지 마라. 2·3단계는 이후 작업 기준으로 남긴다. 먼저 첫 단계가 작동하는 앱을 만들고 검증 결과와 폰에서 눌러볼 순서를 보고한다.

진행 중인 사용자 변경을 보존한다. `reset --hard`, 강제 덮어쓰기, 원본 프로젝트 삭제, 앱 전체 재생성을 하지 않는다. 새 작업 브랜치를 사용하는 것은 가능하되 기존 미커밋 변경을 임의로 커밋하거나 버리지 않는다. GitHub 푸시, 유료 클라우드 빌드, 운영 DB 변경은 이 문서만으로 실행하지 않는다. 필요한 코드와 설정, 마이그레이션은 먼저 검토 가능한 상태로 준비한다.

첫 단계의 성공 경험:

**앱 열기 → 내 위치 확인 → 드라이브 시작 → 외부 내비 사용/화면 잠금 → 앱으로 돌아오기 → 종료 → 실제 경로가 남은 결과 → 히스토리에서 다시 확인.**

코스를 정하지 않아도 이 흐름이 끝까지 작동해야 한다.

## 1. 제품의 중심

사용자는 ‘오늘 드라이브하고 싶다’는 생각으로 앱을 연다. 이 앱은 출발 전의 코스 선택, 주행 기록, 다녀온 길의 기억을 연결한다. 하단 탐색은 세 개만 둔다.

1. **드라이브:** 현재 위치에서 바로 출발한다. 코스 선택은 선택 사항이다.
2. **코스:** 오늘 갈 만한 검증된 길을 고른다.
3. **내 기록:** 다녀온 길을 보고 다시 선택한다.

라우트 그룹은 기존 `app/(tabs)/index.tsx`, `browse.tsx`, `history.tsx`를 재사용한다. 메뉴 명칭 변경을 위해 새 탭이나 별도 홈을 만들지 않는다.

운동 앱에서 가져오는 것은 ‘쉽게 시작하고, 활동이 남고, 다시 하고 싶어지는 흐름’이다. 페이스·칼로리·최고속도 경쟁, 소셜 피드, 복잡한 배지 시스템은 필요하지 않다.

## 3. 완성될 세 화면

### 드라이브 탭

첫 화면의 주요 내용은 다음 순서다.

- 현재 위치가 중심인 지도. 위치 확인 중·권한 없음·위치 확인 완료를 구분한다.
- 큰 **드라이브 시작** 버튼. 기본은 자유주행이며 코스 선택을 강요하지 않는다.
- 선택한 코스가 있으면 코스명과 경로를 표시하고 해제할 수 있다. 버튼은 **이 코스로 시작**으로 바뀐다.
- 그 아래 가까운 추천 코스 최대 3개와 **코스 더 보기**. 추천 자료가 없어도 자유주행은 가능하다.

위치 권한이 없을 때 임의의 기본 좌표를 ‘내 위치’처럼 표시하지 않는다. 기본 서울 지도는 탐색용으로만 보여주며 실제 기록 시작에는 필요한 권한과 위치 상태를 확인한다. 시작 버튼을 누른 의도는 유지하되 권한 실패나 수집 실패를 성공으로 표시하지 않는다.

이미 진행 중인 기록이 있으면 **기록으로 돌아가기**가 기본 행동이다. 탭 전환이나 코스 선택으로 두 번째 기록을 만들지 않는다.

기록 중에는 거리·경과 시간·위치 수집 상태·종료만 우선 표시한다. 외부 내비 사용 중에는 앱 내부 지도를 계속 조작할 필요가 없어야 한다.

### 코스 탭 — 2단계

가까운 실제 코스들을 지도·목록으로 확인하고 상세에서 선택한다. 처음부터 알고리즘 항목을 여러 개 노출하기보다 ‘가까운 순’, ‘짧게 다녀오기’, 검증된 ‘강변/야경’ 같은 조건으로 고르게 한다.

코스 카드의 판단 정보는 이름, 실제 경로 윤곽, 코스 길이, 코스 자체의 예상 시간, 출발점 접근 거리/시간, 확인된 도로 특성이다. 시간 정보의 확보 기준은 2단계 절차를 따른다.

상세의 주요 버튼은 **이 코스 선택**이다. 누르면 드라이브 탭에서 선택 경로를 확인한 뒤 시작한다. 보조 행동 **출발점 길찾기**는 외부 앱에서 시작점까지 안내한다. ‘코스 선택’만으로 GPS 기록을 몰래 시작하지 않는다.

### 내 기록 탭 — 3단계

실제 주행 경로, 날짜, 거리, 시간을 최신순으로 보여준다. 날짜별 구분과 알아보기 쉬운 경로 썸네일을 우선하고 불필요한 통계 대시보드는 만들지 않는다.

기록 상세에서는 결과 이미지 저장·공유, 해당 코스 재선택을 제공한다. 재사용의 구체적인 의미는 3단계에서 구분한다. 자유주행은 알 수 없는 코스나 미완주로 표시하지 않는다.

## 4. 지금 구현할 1단계: 시작과 기록을 완성한다

### 4.1 자유주행과 기존 기록의 호환

`src/lib/trips.ts`에 명시적인 기록 유형을 추가한다. 예를 들어 새 기록은 `kind: 'free' | 'course'`를 가지며, 자유주행은 `courseId: null`, 코스 주행은 유효한 코스 ID를 저장할 수 있다. 정확한 타입은 현재 코드에 맞추되 다음 의미를 지켜라.

- 기존 `courseId`가 있는 기록은 코스 주행으로 읽힌다. 기존 파일을 삭제하거나 일괄 재작성하지 않는다.
- 새 자유주행에는 명시적인 유형을 남겨라. 기존 빈 문자열/잘못된 코스 ID를 무조건 자유주행으로 바꾸지 않는다.
- ‘자유 드라이브’와 ‘코스 정보 없음’을 구분한다.
- 자유주행에서는 `judgeCompletion`을 호출해 완주/미완주를 판정하지 않는다. 실제 기록 거리·시간·경로만 보여준다.
- 서버 업로드는 현재 nullable `course_id`를 이용할 수 있다. 기존 `completed`가 NOT NULL이므로 자유주행 업로드의 호환값을 유지하되 UI에 ‘미완주’라고 표시하지 않는다.
- 현재 서버에 없는 새 필드를 곧바로 전송해 기존 업로드를 깨뜨리지 않는다. 향후 서버에서도 기록 유형을 보존하려면 별도의 호환 마이그레이션으로 다룬다.
- 기록 ID는 세션 시작 시 하나를 발급하고 종료·재시도·로컬 저장에서 그대로 사용한다. 종료할 때마다 새로운 ID를 생성하지 않는다.
- 기존 결과 화면, 히스토리, 서버 업로드의 코스 접근 지점을 모두 점검한다. `getCourse` 등에서 nullable 코스 ID를 안전하게 처리한다.

### 4.2 기록 수명을 화면 수명에서 분리한다

위치 수집을 `app/record/[id].tsx`의 마운트·언마운트에 종속시키지 않는다. 기록 화면은 진행 중 세션을 읽고 조작하는 화면으로 바꾼다.

프로젝트 규모에 맞게 `src/lib/recording.ts`, `src/lib/locationTask.ts` 같은 작은 공용 모듈로 분리할 수 있다. 이름이나 파일 수를 맞추기 위한 분리는 하지 않는다.

- 앱 전체에서 활성 세션은 하나다. 화면 재진입·시작 연타·내비 전환에도 수집기가 중복 등록되지 않는다.
- 세션 ID, 기록 유형, 선택 코스, 시작 시각, 상태, 마지막 저장 지점을 로컬에 보존한다.
- 좌표는 종료 시에만 저장하지 말고 수신한 배치를 순서대로 영속 저장한다. UI와 백그라운드 작업이 같은 파일을 서로 덮어써 좌표를 잃지 않도록 저장 주체를 하나로 정한다.
- 좌표의 측정 시각은 GPS 이벤트 시각을 사용한다. 늦게 배달된 여러 위치를 모두 현재 시각으로 저장하지 않는다. 중복과 순서가 뒤집힌 좌표를 처리한다.
- 기록 중 화면을 떠나는 것은 기록 종료가 아니다. 다시 들어오면 기존 세션을 표시한다.
- 종료는 ‘종료 처리 중 → 수집 중단 확인 → 최종 로컬 저장 → 결과’로 진행한다. 중단·저장 실패 시 재시도할 수 있고, 성공하지 않았는데 완료로 표시하지 않는다.
- 종료된 세션에 늦게 도착한 위치가 붙지 않게 세션 ID와 상태를 확인한다. 종료 버튼 연타로 기록이 여러 개 생기지 않아야 한다.
- 로컬 결과 저장을 서버 응답에 묶지 않는다. 네트워크 없이도 결과를 볼 수 있어야 한다.

### 4.3 백그라운드 위치 기록

설치된 SDK의 타입과 공식 문서를 먼저 확인한다. 현재 `watchPositionAsync`는 포그라운드 업데이트만 제공한다. 백그라운드 위치에는 `startLocationUpdatesAsync`와 TaskManager 작업을 사용한다. [Expo Location](https://docs.expo.dev/versions/latest/sdk/location/)

작업 함수는 화면 effect 안이 아닌 모듈 최상위에서 정의하고, 앱 시작 경로에서 등록 모듈이 로드되게 한다. UI가 없는 실행에서도 활성 세션과 저장소를 읽을 수 있어야 한다. 기존 포그라운드 watcher와 새 수집기가 동시에 좌표를 중복 추가하지 않게 한다. [Expo TaskManager](https://docs.expo.dev/versions/latest/sdk/task-manager/)

현재 설정을 보존하면서 iOS background location 설정과 Android의 필요한 위치 권한·foreground service를 구성한다. Android의 주행 중 알림과 iOS의 위치 사용 표시가 정상 동작해야 한다. 시작할 때 필요한 권한을 단계적으로 요청하고 거부 상태를 처리한다. 새 바이너리가 필요한 변경이며 Expo Go만으로 완료 검증하지 않는다. [Expo 위치 설정](https://docs.expo.dev/versions/latest/sdk/location/#background-location)

사용자가 앱을 강제 종료한 뒤에도 반드시 계속 수집된다고 약속하지 않는다. OS 중단으로 생긴 공백은 보존된 기록으로 복구하되, 잃어버린 좌표를 생성하지 않는다. 기록이 끊긴 구간을 하나의 정상 경로처럼 연결해 거리와 완주율을 부풀리지 말고 구간 단절을 표현한다. 구간 계산 변경 시 기존 기록에 대한 회귀 검사를 한다.

기록 종료 후 위치 수집과 해당 서비스 알림이 실제로 종료되는지 확인한다. 세션이 없을 때 백그라운드 작업이 실행되더라도 좌표를 저장하거나 서버로 보내지 않는다.

- `app/(tabs)/index.tsx`: 현재 위치 중심 지도와 기록 시작을 기본으로 바꾼다. 추천 카드가 없어도 시작할 수 있다.
- `app/(tabs)/_layout.tsx`: 탭 표시명을 드라이브/코스/내 기록으로 바꾼다.
- 기록 화면은 코스 ID 없이도 접근 가능한 진입을 제공한다. 예를 들어 `app/record/index.tsx`에서 활성 세션을 보여주고, 기존 `record/[id]` 진입은 명시적 코스 선택 후 동일한 세션 로직으로 연결한다. 라우트가 충돌하지 않게 하고 기록 구현을 두 벌 만들지 않는다.
- 이전 디자인 수정본의 타이포·버튼·경로 그림은 선택적으로 재사용한다. 이전 홈의 ‘길찾기 중심’ 구조는 복원하지 않는다.
- `app/_layout.tsx`: 공용 기록 초기화와 복구 진입을 연결한다. 복구할 세션이 있다고 새 기록을 자동 시작하지 않는다.
- `app/result/[tripId].tsx`와 `app/(tabs)/history.tsx`: 첫 단계에서도 자유주행을 정상 표시하고 실제 좌표만 그리도록 수정한다.

### 4.5 첫 단계의 완료 기준

자동 검사로 확인할 것:

- [ ] 타입 검사와 Android/iOS 번들 생성.
- [ ] 기존 코스 기록, 자유주행, 찾을 수 없는 코스의 데이터 호환.
- [ ] 시작 연타·재진입 시 단일 세션, 종료 재시도 시 동일 기록 ID.
- [ ] 늦게 도착한 콜백·중복 좌표·종료 후 좌표 무시.
- [ ] 저장 실패 후 복구 및 중단된 기록의 구간 분리. 새 저장 로직에는 이 동작을 검증하는 의미 있는 테스트를 작성한다.

실기기로 확인할 것:

- [ ] 코스 없이 시작 → 이동 → 종료 → 결과 → 내 기록.
- [ ] 기존 공식 코스를 선택한 기록도 정상 동작.
- [ ] 기록 중 외부 내비로 전환하고 이동한 뒤 돌아와도 같은 세션이며 실제 경로가 남음.
- [ ] 화면을 잠근 상태에서 이동 후 복귀해 기록 유지 확인. 단순히 정지한 채 기다리는 시험만으로 통과 처리하지 않음.
- [ ] 위치 권한 거부·위치 서비스 꺼짐·수집 실패를 ‘기록 중’으로 숨기지 않음.
- [ ] 종료 후 추가 수집과 서비스 알림 중단.
- [ ] 앱 중단 후 재실행 시 저장된 초안을 찾고 복구 가능. 수집되지 않은 구간은 누락으로 구분.
- [ ] 자유주행 결과 PNG 저장·공유와 서버 미설정 상태의 로컬 이용.

가능하면 iOS와 Android 개발 빌드에서 각각 수행한다. 연결된 폰이 없으면 코드·자동 검사는 끝내고 실기기 항목은 미검증으로 남긴다. 번들 생성 성공을 백그라운드 동작 검증으로 바꾸어 말하지 않는다.

**첫 단계 보고는 ‘바꾼 파일 / 폰에서 눌러볼 순서 / 통과·미검증 항목’으로 끝낸다. 그다음 아래 2단계를 진행한다.**

## 5. 다음 2단계: 선택할 이유가 있는 코스 약 10개

첫 단계와 동시에 코스 수를 채우려고 임의의 명소나 좌표를 생성하지 않는다. 초기 서비스 지역을 기준으로 실제 자료가 있는 코스를 약 10개 확보한다. 기존 데이터가 서울 서부·경기 북서부에 있다는 것은 참고이며, 사용자가 원하는 지역을 확인하기 전 전국 서비스 범위로 단정하지 않는다.

1. 기존 `docs/admin-courses.md`와 `scripts/fill-courses.js`를 읽어 관리자 검증 절차를 재사용한다.
2. 코스마다 실제 출발·도착·중간 경로, 주행 가능한 도로, 경로 출처와 확인일을 기록한다. 지도 경로 요청의 라이선스·사용 조건을 확인하고 공개 데모 서버를 대량 호출하지 않는다.
3. 마곡–가양 코스는 현재 좌표가 3개다. 점선 표현을 유지하고, 관리자가 경로를 검증하기 전 임의의 매끈한 선으로 바꾸지 않는다.
4. 정확한 경로와 이동 가능 여부를 확인한 항목만 `is_official: true`로 공개한다. 검증된 코스가 6개라면 6개만 노출하고 나머지 4개를 가짜로 채우지 않는다.
5. 초기 제목은 **추천 코스**다. 인기순은 실제 이용 집계가 있기 전에는 노출하지 않는다. 향후 집계는 기간을 정한 고유 이용자 수와 재방문을 분리해 설계한다. 개인 경로 원본을 공개 조회 가능하게 만드는 방식으로 집계하지 않는다.
6. 기본 가까운 순은 우선 코스 출발점까지의 실제 위치 기반 거리로 구현할 수 있다. 직선거리라면 ‘직선거리’로 표시한다. 실제 도로 접근 시간이 없는 경우 `분`으로 꾸며내지 않는다.
7. 기존 ‘접근 거리 + 코스 거리 + 귀가 거리’를 40km/h로 나눈 값은 실시간 내비 ETA가 아니다. 코스 자체 예상 시간, 출발점까지 접근 정보, 전체 예상 왕복 시간을 구분한다. 추정 근거를 명시하고 알 수 없는 시간은 미표시한다.
8. 풍경·야간 적합성·좁은 구간·커브 같은 특성은 확인된 자료만 표시한다. 근거 없는 ‘난이도 3/5’나 ‘초보도 안전’ 같은 단정을 하지 않는다.
9. 조건은 초기에는 가까움·짧은 코스·검증된 테마 정도로 제한한다. 데이터가 없는 필터는 만들지 않는다.
10. 상세의 **이 코스 선택** → 드라이브 탭에 선택 상태 반영 → **이 코스로 시작** → 종료/결과 흐름을 완성한다.

완료 기준: 현재 위치와 선택 조건을 바꾸면 적절한 실제 코스가 나오고, 추천 이유를 설명할 수 있으며, 선택한 코스와 기록된 코스 연결이 일치한다. 추천 결과가 없어도 자유주행은 사용할 수 있다.

## 6. 다음 3단계: 내 기록에서 다시 출발

- 실제 기록 경로·날짜·거리·시간을 중심으로 목록과 상세를 구성한다. 기록의 식별에 도움이 되는 이름을 사용한다.
- 공식 코스 기록의 **이 코스 다시 선택**은 현재 유효한 코스 상세/선택으로 연결한다. 현재 위치에서 접근한 뒤 새로운 세션을 만든다. 예전 기록을 수정하거나 복사 저장하지 않는다.
- 자유주행 기록은 지난 경로를 참고 이미지로 보여주고 **여기서 새 드라이브 시작**으로 현재 위치 기반 새 세션을 연다. ‘예전 경로 그대로 안내’라고 표시하지 않는다. 자유주행 경로를 실제 재탐색 가능한 코스로 변환하는 기능은 별도 범위다.
- 코스가 삭제·비공개되었어도 과거 기록은 읽을 수 있게 한다. 현재 선택할 수 없는 코스에 재선택 버튼을 활성화하지 않는다.
- 외부 내비의 기존 동작은 **출발점까지 안내**다. 전체 경로 재주행을 보장하려면 경유지 전달 등 별도 검증이 필요하다. 현재 기능명과 화면 문구로 이를 혼동시키지 않는다.
- 실제 경로가 없는 기록에 예정 코스의 선을 그리지 않는다.
- 기존 결과 이미지 저장·공유를 유지하고, 자유주행에는 완주/미완주 대신 기록 사실을 표시한다.

완료 기준: 지난 기록을 보고 원하는 코스를 다시 선택하여 새 기록을 남길 수 있고, 기존 기록과 새 기록은 서로 독립적으로 보존된다.

## 7. 디자인 기준은 세 흐름에 맞춰 적용한다

밝은 지도, 충분한 여백, 큰 거리·시간, 파란 주요 액션, 읽기 쉬운 한국어를 기본으로 한다. 기록 중에는 큰 숫자와 최소 조작을 강조한다. 결과는 4:5 이미지로 실제 경로를 담는다.

기존 `src/ui/theme.ts`, `RouteSketch.tsx`, Ionicons를 재사용한다. 화면 제목·지표·단위의 크기를 구분하고 글자 확대·안전영역·48dp 이상 조작 영역·로딩/오류/비활성 상태를 함께 만든다. 이름이 긴 코스나 작은 폰에서 기능 버튼이 가려지면 완료가 아니다.

기존 패치의 모든 숫자와 문구를 그대로 옮기는 것보다 ‘지금 시작 → 길 선택 → 기록 → 다시 출발’이 자연스러운지가 우선이다. 화면마다 새로운 장식이나 기능을 추가하지 않는다.

## 8. 문서를 유지하는 방법

이전 지침의 제품 제약과 충돌하는 줄은 실제 코드 작업에서 함께 갱신한다. 다만 다른 사용자의 규칙이나 아직 관련 없는 설정까지 정리하지 않는다.

1단계가 끝나면 무엇을 실제 구현했고 무엇을 아직 검증하지 못했는지 프로젝트에 남긴다. 이어지는 실행에서는 완료한 단계부터 다시 시작하지 말고 2단계, 3단계 순서로 진행한다. 실기기·자료·인증이 필요한 항목은 준비한 결과와 정확한 남은 조건을 설명한다.

코드 구현과 검증의 책임을 사용자에게 통째로 넘기지 마라. 사용자는 폰으로 핵심 동작을 확인하고 원하는 사용감을 판단할 수 있어야 한다.
